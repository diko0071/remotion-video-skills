  the composer. One object morphs through the whole intro — zero crossfades.

  Prompt types fast (real, specific prompt: "Analyze the most viewed
  commercials using the YouTube Data API, reverse-engineer them, and generate
  50 ads for my product via Higgsfield MCP"). Cursor arrives, clicks send
  (Fable 5 pill = send button).
- **8.5-12.4 Chat work.** Claude-style response streams ("Got it. Analyzing
  your product first… This is FabVital C-Boost Gummies — vitamin C, orange
  flavor, zero sugar…"), tool line "Connecting to YouTube Data API". White

- **12.4-15.2 Result avalanche.** "Generating videos…" rows of video
  thumbnails STACK bottom-up, faster and faster, rows land with motion blur,
  camera pulls back as the wall grows. Cuts at 12.43 / 13.83 / 15.23 = ~1.4s

- **15.2-17.7 Endcard.** Hard cut to white: "Claude Fable 5 × Higgsfield MCP /

→ tail. Loudness -13.5..-7.6 LUFS momentary (modern-loud, compressed).

**Steal:** single-object morph intro; velocity-proportional motion blur;
result avalanche with pull-back; endcard color flicker; prompt text that reads
like a real power-user, not marketing copy.

# The distilled motion language (why it reads expensive)

1. **Hard cuts + morphs. Never soft crossfades.** Scene changes are either a
   hard cut on the musical grid or a physical transformation of an on-screen
   object. Slow crossfade = cheap. (Our engine's default cross-fade should be
   reserved for background-only swaps.)
2. **One object carries the intro.** Logo → pill → plus → card → composer:
   matter is continuous, the viewer never loses the thread. Match-cut thinking.
3. **Motion blur on every fast move.** Directional blur while text slides,
   scale blur while cards expand, blur on avalanche rows landing. Settle to
   sharp. Velocity-proportional: big move = big blur, rest = crisp.
4. **Cut lengths live on the music grid.** Bars (~1.4-2s at 110-125 BPM) for
   normal scenes, beats for montage bursts. Machine-gun payoff: 2-6 cuts/sec
   for at most 2-3s, placed at the energy peak.
5. **Macro-crescendo:** lockup (1.5-2.5s) → setup scenes (4-8s) → optional
   long real-work take (10-20s, pace from inside the capture) → results
   montage with TIGHTENING cuts → machine-gun burst → hard cut to endcard
   (3-5s). Shot length compresses toward the climax, releases at the end.
6. **The output takes over the frame.** Payoff content plays FULL-BLEED — UI
   chrome vanishes. Sell the result, not the browser. Return to UI afterwards.
7. **Status text is typography.** Progress states appear as big centered type
   that shrinks into a corner status line (with inline logo chips) when work
   starts. Highlight-boxes draw around the key word of a headline.
8. **Result avalanche ending** for "scale" claims: rows of outputs stack with
   accelerating rhythm and motion blur, camera pulls back, hard cut to white
   endcard. (Validated: our mcp-claude dashboard avalanche is this pattern.)
9. **Screen recordings get a virtual camera.** Zoom to the active region, pan
   between panels, speed-ramp dull stretches, float caption pills anchored to
   regions. Never a static full-frame capture.
10. **Endcards are alive for 2-3 frames at a time:** one word flickers through
    accent colors; otherwise static lockup + small-caps availability line.
11. **Music structure:** impact hit on the first lockup, a breath (dip) during
    the hero morph, loud compressed bed through work, montage rides the peak,
    tail/decrescendo only in the last 1.5-5s. Music NEVER ends early and never
    plateaus quietly — it is mixed loud (-8..-13 LUFS momentary).
12. **Real prompts, real cursor.** Prompt copy reads like an actual power
    user (specific APIs, numbers, product names). Cursor visibly clicks send.
13. **One organic motif over clean UI** (halftone butterflies, particle ring,
    paper-cut world): a single non-UI texture layer makes the cleanliness
    read as intentional. One motif, not a collage.
14. **Deliverable gets its own beat:** the URL pill / "All done and ready for
    deploying" check-diagram is a 2s scene, not a footnote.
